# Domain Docs

本项目采用 single-context 领域文档布局。

## 探索代码前

- 阅读根目录的 `GLOSSARY.md`。
- 阅读 `docs/adr/` 中与当前工作相关的架构决策记录。
- 若未来存在 `GLOSSARY-MAP.md`，按其中的指引读取相关上下文的词汇表。

上述文件尚不存在时，直接继续工作。
由 domain-modeling 技能在术语或决策明确后按需创建。

## 文档位置

- 领域词汇表：`GLOSSARY.md`
- 架构决策记录：`docs/adr/NNNN-<主题>.md`

## 使用领域术语

Issue 标题、设计方案、假设和测试名称中的领域概念，
使用词汇表定义的名称。

遇到未收录的概念，先核对现有术语；确有缺口时，
记录下来供 domain-modeling 处理。

## 处理决策冲突

方案与已有 ADR 冲突时，明确指出相关 ADR，
说明冲突内容和重新讨论该决策的理由。

# 彻底删除与批量记录操作访谈

日期：2026-10-25。状态：Q1—Q7 已获用户逐项确认，已在 0.1.4 实现并安装；验收记录见 `../development/batch-records-milestone.md`。未操作个人账本中的记录。

## 用户要求

在可恢复已删除记录的界面增加“彻底删除”，并支持批量删除。

## 已核对的现状

- 当前“删除”是记录作废：保留原内容及版本历史，可恢复、可撤回；已删除记录不计入余额。
- 资金记录支持账户筛选、有效/已删除状态筛选，尚无多选和批量操作。目前真实账本功能只有手动入金，导入及批次撤回尚未实现。
- 入金记录与其版本历史有关联；彻底清除需要同时决定历史是否保留，以及旧撤回入口是否失效。
- 账户有历史时锁定币种、不能作为空账户删除；现有判断包括已删除记录。最后一条记录被彻底清除后的账户规则需要明确。
- 旧版迁移快照独立存在，删除当前账本记录不会自动清理既有快照或用户备份。

现有“记录作废”与 PRD AC30、已完成 Issue #18 的可恢复规则保持有效。新增不可恢复操作需要单独命名，并明确对 ADR-0002 保留记录及来源原则的例外。

## 第一轮已确认

- Q1：仅“已删除”记录提供彻底删除，有效记录先作废。用户选择推荐项。
- Q2：有效列表增加批量删除，已删除列表增加批量恢复和彻底删除；全选限当前筛选结果，切换账户或状态清空选择。用户选择推荐项。

## 第二轮已确认

- Q3：彻底删除同时清除所选记录及其全部修改历史，软件内不可恢复或撤回；独立备份和升级快照保留，不承诺磁盘安全擦除。用户选择推荐项。
- Q4：彻底删除弹窗显示所选账户范围和条数，说明不可恢复，输入“彻底删除”后才能确认。普通批量删除只需确认，批量恢复无需输入文字。批量操作全部成功或全部不变，记录被修改、状态改变或不存在时提示刷新，不静默跳过。用户选择推荐项。
- Q5：本次仅交付现有手动入金；CSV 导入、买卖及关联交易的删除规则随各自任务处理。用户选择推荐项。

## 第三轮已确认

- Q6：账户最后一条记录及历史清除后重新按空账户处理，允许修改币种或删除账户。仍有有效或已删除记录时保护不变。用户选择推荐项。
- Q7：普通批量删除与恢复提供一次“撤回本次操作”，整批还原；相关记录后续变化时拒绝过期撤回。重启后通过状态及单条历史恢复，彻底删除不能撤回。用户选择推荐项。

## 实施与验收

沿用既有、已确认的测试边界：Ledger 公开应用用例使用独立临时账本，核对记录、余额、历史及重启结果；少量 React 操作流程只替换外部 Tauri IPC 边界，验证选择范围、确认、撤回与错误提示。不以 SQL 侧查验证，不在个人账本创建或删除验收数据。

1. 已删除手动入金可单条或多条彻底删除，清除其全部历史，余额不再次减少，旧历史恢复和撤回无法重建记录，重启后仍不存在。
2. 普通批量删除、恢复及整批撤回，以同一原子操作提交；空选择、重复记录、版本过期、记录不存在、状态不符或恢复余额溢出均拒绝，记录、余额和历史全部不变。
3. 当前筛选结果可复选、全选、取消选择；切换账户或记录状态清空选择。提交后清空选择并刷新账户保护状态；操作期间禁止重复提交及变更选择。
4. 彻底删除弹窗显示实际所选账户和条数，必须输入“彻底删除”才能提交。失败保留确认范围并提供刷新入口，刷新后重新选择；清除成功后移除旧历史和撤回入口。
5. 最后一条彻底清除后可改账户币种、删除空账户；仍有任意记录时保护不变。已有独立备份和快照不修改。
6. 完成后按 main 固定基准分别审查 Standards 与 Spec，执行既有测试和 Windows 打包/安装回归，交付升级安装包。

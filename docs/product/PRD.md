## Problem Statement（问题陈述）

个人投资者希望统一观察美股、A 股和港股的股票、ETF 与账户现金，理解自己的真实投资结果。不同券商、市场和币种中的记录分散，追加本金、账户转账、分红、税费和汇率又会影响资产变化，简单相加市值或照搬券商展示收益不能完整回答以下问题：

- 目前有多少资产，分别放在哪些账户、市场、行业和证券中？
- 投资本身表现如何，个人投入资金实际获得了怎样的回报？
- 盈亏来自哪些持仓，分红收到了多少，还有多少已确认但未到账？
- 资产和收益随时间如何变化，今天的估值使用的是什么时间的报价？
- 导入或修正一份交易记录后，能否核对结果，并在需要时恢复数据？

Graham 面向需要管理多市场、多币种投资记录的个人投资者。券商专用格式的计划适配对象包括华龙证券和兴业证券，具体支持情况以适配验证为准；该计划不对应任何个人的账户情况。界面通过可点击原型验证信息组织和主要操作。

## Solution（解决方案）

### 产品定位与首版范围

提供中文 Windows 桌面软件，将个人投资记录保存在本地，支持手动录入、券商文件导入、盘中行情更新、收益计算和组合分析。

| 维度 | 已确认要求 |
| --- | --- |
| 使用者 | 管理个人投资记录的投资者 |
| 平台 | Windows 桌面安装和使用 |
| 市场 | 美股、A 股、港股；具体账户及交易渠道以真实记录核对 |
| 资产 | 股票、ETF、账户现金 |
| 账户 | 分别记账，支持合并总览 |
| 券商适配 | 优先华龙证券、兴业证券，具体字段依实际导出样本确定 |
| 记录来源 | 文件导入与手动补充、修正 |
| 币种 | 保留原币；汇总默认人民币，可切换美元和港币 |
| 行情预算 | 0 元；允许额外免费行情账号 |
| 行情时效 | 交易时段以约 5 秒更新估值为目标；免费权限不足时接受明确标记的延时行情 |
| 历史曲线 | 按日绘制，从可验证起点开始 |
| 收益 | 投资表现收益率、个人资金回报率、已实现及未实现盈亏、税后分红 |
| 保存与恢复 | 本地保存，支持备份和恢复 |

约 5 秒的估值更新目标与行情源报价时效分别展示。刷新一次旧报价不会将其变成实时行情。自动刷新报价也不代表自动同步券商账户交易。

### 页面与信息结构

整体采用用户已选择的 A 全景仪表盘结构，使用酒红与白色配色、左侧导航；页面优先展示金额的币种、所选账户范围和数据时间。白色用于侧栏和内容表面，酒红用于品牌、主要操作、选中态及图表，盈亏与异常状态另保留语义标识。

| 页面 | 主要内容 | 关键操作 |
| --- | --- | --- |
| 总览 | 总资产、投资净盈亏、两种收益率、历史收益曲线、持仓分布、行情状态 | 切换账户范围、汇总币种和时间范围，进入明细 |
| 持仓 | 股票与 ETF 数量、成本、估值、已实现及未实现盈亏；账户现金单列 | 按账户、市场等筛选，查看证券和账户明细 |
| 交易与导入 | 买卖、资金进出、转账、换汇、手动修正和导入结果 | 预览文件、处理错误与重复项、确认入账、核对差异 |
| 分红 | 税前金额、扣税、实收、待到账状态，按账户或证券汇总 | 查看分红明细，补充或修正实际记录 |
| 组合分析 | 市场、币种、行业、证券维度分布，以及盈亏和分红贡献 | 切换分析维度和账户范围，追溯到贡献明细 |
| 设置 | 账户、汇总币种、行情连接与权限状态、本地备份与恢复 | 配置免费行情账号、检查状态、导出备份和恢复 |

### 核心用户流程

1. **建立账户与起点**：建立投资账户；有完整记录时导入历史记录，历史不足时从可核对日期建立期初快照。
2. **导入与核对**：选择券商或记录类型，预览识别结果，处理校验错误和重复项，核对后确认入账。
3. **查看结果**：进入总览，查看账户或合并资产、投资表现、资金回报、分红和资产分布，再进入明细解释结果。
4. **更新行情**：交易时段刷新持仓估值；报价延迟、断线、缺失或手动输入时显示对应状态及日期。
5. **修正与恢复**：修正记录后重新计算受影响结果；通过本地备份恢复同一组投资记录和配置。

空账户显示建账与导入入口。记录不足、报价缺失和计算不可用均显示具体原因，不以 0 伪装正常结果。模拟数据在界面中清晰标识。

## Implementation Decisions（实现决策）

### 已确认的业务边界

- 以投资账户为独立记账范围，以所选账户集合为合并范围。内部转账的分类随计算范围变化，合并时配对两端。
- 交易记录、资金记录、分红记录、行情与汇率各自保留来源、币种和所属时点，避免把刷新时间当成报价时间。
- 账户记录通过文件导入和手动修正更新；市场行情独立接入，刷新行情不改变证券持有数量。
- 建账起点使用可核对历史或期初快照，期初以前的表现不反推为已知收益。
- 成本采用移动加权平均口径；已实现盈亏、未实现盈亏与分红分别解释，组合总结果避免重复计入。
- 投资表现收益率采用时间加权的观察口径，个人资金回报率采用资金加权的观察口径；曲线默认日频。
- 默认展示已记录实际税费后的净结果，保留费用和税的独立明细。
- 原币记录保留，汇总展示可切换人民币、美元和港币；历史估值使用对应日期的历史汇率。
- 行情预算为 0 元，实际市场覆盖和时效依可验证的免费权限决定；允许明确标记的延时行情和有日期的手动价格。
- 缺失价格或汇率时，相关估值或汇总标记为不完整，并列出缺失项；保留可用部分的结果，不能将缺失项当作零后展示完整总额。
- 未识别的证券、交易类型和特殊账务事件进入待处理状态；导入预览与校验负责阻止不完整记录静默入账。
- 证券列表与详情仅以文字展示；取消证券/公司/基金 Logo、占位图标、下载、缓存、映射与资源校验。证券身份仍供核算、行情和行业分类使用，Graham 自有品牌及软件图标保留。（2026-10-27 用户决定，替代原 Logo 三条要求。）

### 产品能力划分

围绕一条完整流程组织能力：输入投资记录与市场数据，形成可核对的资产和收益结果，再向页面提供查询结果。

该流程需要覆盖记录导入与校验、账户记录维护、行情与汇率接入、持仓成本和收益计算、页面查询及本地备份恢复。桌面工程已确认 Tauri 2 + React/TypeScript、shadcn/ui、ECharts 和本地 SQLite；当前用户安装 .exe，优先支持干净机器离线安装并提供 WebView2 离线安装程序，首版手动升级，升级前备份并保留账本与缓存。本机数据库暂不加密、不设置应用登录密码，提供加密导出备份；备份密码由用户保管，软件不保存，遗失无法解密该备份。AKShare 优先负责 A 股和港股，yfinance 优先负责美股，接口需先实测并保留来源与报价时间。先贯通手动录入及统一 CSV 导入，保留华龙、兴业专用样本适配目标。正式安装包内置固定 Python 运行时及 AKShare/yfinance 依赖，开发机现有 Python 仅用于开发；具体发布版本在兼容性验证后固定。具体接口覆盖、时效及券商字段仍待实测；上述方案尚未实现。

原型使用清晰标记的模拟数据验证六个页面及主要交互；原型完成不等同于真实导入、计算引擎或行情接入完成。

## Testing Decisions（测试与验收决策）

### 已认可的主要验收边界

以完整应用用例为主要边界：给定记录、行情、汇率和时间，执行导入、确认、修正或刷新后，验收账户、持仓、现金、收益与图表查询的外部结果。尽量通过同一条用例流程覆盖导入适配与计算，避免为内部函数、组件拆分或实现细节编写重复测试。

补充少量真实界面流程检查：导航、账户与币种切换、导入确认、错误提示和备份恢复入口。真实行情与券商导出适配另需使用实际账号权限和脱敏样本验证，模拟数据不能替代这一验收。

目前没有应用代码或既有测试，可复用的测试先例尚不存在。后续使用固定时钟、固定报价和汇率样例，使每次验证可以重复核对；普通自动化验收不依赖实时网络波动。

### 可核对的验收场景

| 编号 | 场景 | 预期外部结果 |
| --- | --- | --- |
| AC01 | 首次打开且没有记录 | 显示建账和导入入口，不展示虚构个人资产或收益 |
| AC02 | 两个账户持有同一证券 | 单账户结果保持独立；合并数量和资产与账户结果可核对 |
| AC03 | 导入一份有效券商样本 | 预览正确展示字段与币种；用户确认前账本不变，确认后结果可追溯 |
| AC04 | 再次导入同一份记录 | 显示重复项，资产、现金、分红和收益不被重复计算 |
| AC05 | 文件存在日期、币种、证券或交易类型错误 | 列出具体行与原因；错误记录在修正前不入账 |
| AC06 | 手动修正已确认的记录 | 相关持仓、现金、成本和历史结果重新计算，并能核对修改后的来源 |
| AC07 | 从期初快照开始建账 | 从该日计算后续表现；此前区间显示数据不足 |
| AC08 | 资产为 100,000 元且没有行情涨跌，再入金 50,000 元 | 总资产变为 150,000 元；该次入金不产生投资盈利，也不单独抬高投资表现收益率 |
| AC09 | 华龙向兴业转账 10,000 元且没有手续费 | 两账户分别体现转出和转入；合并资产不因内部转账变化，合并外部投入不增加 |
| AC10 | 上述转账另发生一笔已记录手续费 | 手续费在净结果中只计一次，能够从资产变化追溯到该费用 |
| AC11 | 同一证券买入 100 股、每股 10 元，再买入 100 股、每股 20 元，均无税费 | 持有 200 股，总成本 3,000 元，平均单位成本 15 元 |
| AC12 | 在 AC11 后按每股 18 元卖出 100 股，无税费，剩余报价为 18 元 | 剩余成本 1,500 元，已实现盈亏 300 元，未实现盈亏 300 元；现金与持仓同步核对 |
| AC13 | 分红税前 100 元、扣税 10 元、实际到账 90 元 | 税前、扣税、实收可分别查看；现金只增加 90 元，组合净收益不重复计分红 |
| AC14 | 一笔待到账分红转为已到账 | 应收与现金状态正确转换，同一笔分红不会因到账再次作为新增收益或新增本金 |
| AC15 | 切换汇总币种或查看不同历史日期 | 原币记录不变；展示使用对应币种及日期汇率，并清晰注明单位 |
| AC16 | 某日缺失历史价格或汇率 | 受影响的估值、收益或曲线点标明数据不足；不使用零或虚构数据补齐 |
| AC17 | 行情为延时、断线、无权限或没有报价 | 状态和真实数据时间可见；保留有效历史值，不把刷新时间显示成新的报价时间 |
| AC18 | 自动刷新时行情源仍返回同一条报价 | 软件更新时间可变化，但报价时间保持原值，不能将其标为新实时成交数据 |
| AC19 | 切换曲线至近一个月、今年以来、全部或自定义区间 | 日期范围和日频数据一致，显示口径与所选账户范围一致 |
| AC20 | 查看组合分布与盈亏、分红贡献 | 已分类部分能与相关明细核对；未分类项显式呈现，不静默丢弃 |

| AC29 | 在未安装 Python 的干净 Windows 环境中断网安装并启动 | 安装包带齐必要运行时和 Python 数据进程依赖；应用能启动、读取已有账本并显示 Graham 品牌图标，不要求配置系统 Python。需要联网的市场数据请求显示其实际状态 |
| AC30 | 修改或删除错误账户记录 | 重新计算余额及相关结果；删除采用可恢复作废，保留原始内容和修改历史，操作后可撤回，重启后仍可通过历史恢复 |
| AC31 | 修改或移除投资账户 | 可改名；有历史记录时锁定币种且仅可归档，归档不改变合并资产；无历史记录时可修改币种或删除 |
| AC32 | 撤回错误导入 | 支持单条纠错与按批次撤回，保留原始行、批次和操作来源，有依赖时先提示影响并阻止不完整撤回；随导入功能交付 |

| AC34 | 彻底删除已作废手动入金 | 单条或批量清除当前账本中的所选记录及全部历史；在已删除列表点击“彻底删除”直接执行，无文字输入及二次确认（2026-10-27，Issue #22 覆盖原规则），软件内无法恢复或撤回，不再次改变余额；独立备份和快照不受影响，不承诺安全擦除 |

收益算法正式验收还需补充独立核对的时间加权、资金加权、费用、汇率及公司行动样例。资金加权结果无唯一解或无法计算、计算范围起点无有效资产等情况，应显示原因，不能伪装为 0% 正常回报。

### 分阶段完成标准

1. **页面原型**：六个页面和主要交互可体验，模拟数据明确标识，用户能评价布局与操作。此阶段不承诺真实金融计算已经通过验收。
2. **本地记录与计算**：导入和手动修正贯通，使用可核对样例通过记录、现金、成本和收益验收，备份恢复可验证。
3. **真实券商与免费行情**：两家真实脱敏样本适配经过核对，免费账号实际覆盖与时效已验证，异常状态可复现。
4. **Windows 首版交付**：能够安装启动，记录重启后保留，主要流程和前述验收通过；存在的市场或数据限制清楚列明。正式安装包资源检查、Graham 品牌/快捷方式图标、关闭开发服务器后的离线启动和账本升级保留验收均是交付门槛；未通过时不能仅凭网页原型展示成功判定此功能完成。

## Out of Scope（首版不包含）

- macOS、Linux、手机端和多人协作服务。
- 券商自动下单和交易执行，以及把行情更新等同于账户交易自动同步。
- 付费行情订阅，以及对所有市场免费交易所实时行情的保证。
- 依靠不完整记录推测建账前收益，或把未识别账务事件静默当作普通买卖。
- AI 买卖建议、自动调仓和税务申报；第一版聚焦持仓分布、收益与分红贡献。
- 云端保存个人投资记录和跨设备自动同步。

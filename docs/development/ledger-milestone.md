## 测试边界与范围

- 账户与入金用例：通过公开账本接口建账户、录入记录、关闭并重开真实临时 SQLite，再通过查询接口核对日期、原币金额、余额和来源；不直接读取内部表验证结果。覆盖持久化、精度与校验，不能替代安装器或 WebView 的验收。
- 桌面界面：在原生 IPC 边界提供受控响应，验证空账本、建账入金表单及失败保留输入；不模拟账本内部协作者。随后在真实 Windows 构建产物检查表单与重启保存。
- 首次为空，不使用原型的虚构持仓或收益。多种币种余额保留原币，不在本任务实现行情、换汇或收益。

## 构建与阶段边界

本机缺少 Rust/C++ 工具且进程无管理员权限；安装 Microsoft 构建工具的动作被自动批准审查拒绝，理由仅返回 `blocked by policy`。使用 GitHub 官方 Windows 构建环境生成开发安装包，本地继续类型检查和界面用例验证。

正式程序通过 Tauri 原生调用读取 SQLite，不通过原型服务器或 localStorage 持久化账本。数据目录为当前用户的本地应用数据目录 `com.graham.portfolio` 下的 `ledger.sqlite3`；目录创建失败时显示启动失败，不清空或重建已有账本来伪装恢复成功。

本项为首个开发里程碑。加密备份、买卖成本、真实导入、行情 Python 进程、收益曲线与正式发布验证分别见后续子任务，不能由本项通过推导出完整软件已交付。
